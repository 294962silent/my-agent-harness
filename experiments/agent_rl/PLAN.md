# Agent RL 数据与奖励管道 · 一周计划

> 目标岗位：Agent RL 后训练
> 时间：5 个工作日，本人每天 2–3 小时掌握方向，其余交由 agent 执行
> 成本预算：DeepSeek 约 ¥25–35
> 仓库：`C:\Users\MLL\Desktop\my-agent-harness`

## 一、总目标（一句话）

用现有 harness 驱动 DeepSeek，在 **Docker 沙盒**里跑 **100 个模板化编码任务**，产出 **标准轨迹 + 可验证奖励 + DPO 偏好对**，并用 **pass^k（稳定性）/ pass@k（采样上限）/ gap（训练空间）** 三个指标量化。

**不做的事**：不训练模型（一周不可能跑通 GRPO）。做的是「训练数据与奖励层」——RLVR 的核心是可验证奖励，不是 PPO 循环。

## 二、已确定的 7 个决策

| # | 决策 | 选择 |
| --- | --- | --- |
| 1 | 本人时间投入 | 每天 2–3 小时掌握方向，其余由 agent 执行 |
| 2 | 任务来源 | **B：模板 + 变量生成**，5 模板 × 20 变体 = 100 题 |
| 3 | 模板集合 | T1 单文件 bug 修复 / T2 功能补全 / T3 多文件重构 / T4 配置数据变换 / T5 CLI 工具实现 |
| 4 | 产出形态 | **C：B + 偏好对构造**（DPO pair 作为交付，时间不够也保） |
| 5 | 模型与采样 | **C：单模型 deepseek-v4.1-flash + 难度自适应校准** |
| 6 | 一致性指标 | **pass^k 与 pass@k 双报，并报 gap** |
| 7 | 叙事 | **B 为主体（有 ρ、有增益、有偏好对数量），C（反直觉发现）作为加分** |

## 三、核心指标定义（写进报告的口径）

```
对任务 T，采样 k=5 次：
  pass^k = E[∏ 1(success_i)]      # 五次全对的概率 → 稳定性（τ-bench 口径）
  pass@k = 1 - C(n-c,k)/C(n,c)    # 至少一次对  → 采样上限（Codex 口径）
  gap    = pass@k - pass^k        # 训练空间：reward 选得准能补多少
```

另报：
- **5 模板 × pass^k 矩阵**（哪类任务最不稳定）
- **失败模式分布**（超时 / 工具误用 / 提前放弃 / 改错文件）
- **奖励与人工判定的一致性**（人工抽查 30 条，算 Spearman ρ）
- **偏好对数量**与训练集覆盖率

## 四、D1–D5 排期

### D1 · Docker 沙盒打通
**交付物**：单任务容器内跑通一次 harness 调用

- 写 `experiments/agent_rl/sandbox.py`：镜像 + 挂载 workspace + 超时 + 资源限制
- 基础镜像：`python:3.11-slim` + git + pytest，预构建一次复用
- 验收：`python -m experiments.agent_rl.sandbox --demo` 能在一个容器里让 agent 读文件、改文件、跑 pytest

### D2 · 任务生成器 + 4 个确定性判定
**交付物**：100 个任务全部落盘，可独立运行

- `tasks/` 下 5 个模板，每个 20 变体（参数化：文件名、bug 类型、函数名、数据规模）
- 每题产出：`task.json`（题面 + 初始 commit）+ 判定函数 + 期望结果
- 判定**全部是纯代码**：pytest 退出码 / 文件比对 / shell 断言
- 验收：`--list` 出 100 题，随机抽 5 题用参考解法跑一遍全绿

### D3 · 轨迹导出器
**交付物**：标准 schema 的轨迹 JSONL

- `trajectory.py`：把会话消息 + 工具事件流转成
  `{task_id, model, messages[], tool_calls[], reward, meta{latency, tokens, steps}}`
- 同时导出 verl 兼容的 `prompt/response` 视图（能直接喂框架）
- 验收：单题跑出 1 条轨迹，字段齐全，人能读懂

### D4 · 难度校准 + 沙盒池并发
**交付物**：通过率分布图 + 筛选后的任务集

- 100 题 × 1 次采样 → 通过率
- 保留通过率 **20%–80%** 的题（目标 60–70 题）进主实验
- 并发执行 N 个容器（默认 4，可配）
- 验收：跑完输出「难度分布」表，被排除的题有原因记录

### D5 · 主实验 + 偏好对 + 报告
**交付物**：报告 + 图 + 偏好对数据

- 筛选后任务 × k=5 采样 → pass^k / pass@k / gap
- 人工抽查 30 条打标 → 与奖励函数比 → Spearman ρ
- 每任务取最优/最差轨迹 → DPO 偏好对
- 失败聚类（C 加分项的来源）
- 验收：`REPORT.md` 含三个核心数字 + 矩阵 + 失败分布

## 六、验收标准（周结束时要能回答）

## 七、风险与预案

| 风险 | 预案 |
| --- | --- |
| Docker 装不上/镜像拉不下来 | 退到进程级沙盒（临时目录 + 子进程），结论打折扣但能跑 |
| 任务太难，全 0 | 校准阶段降难度（减少 bug 数量/给更多上下文） |
| 任务太简单，全 1 | 加干扰文件、隐藏测试、要求不许改测试文件 |
| 一周跑不完 D5 | 优先保：轨迹 + 奖励 + pass^k；砍偏好对到 30 对 |
| 成本超预算 | 校准阶段用较短 max_tokens，主实验再放开 |
