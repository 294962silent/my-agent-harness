## 三、最重要的三个发现

### 1. 长程任务的难度模型

```
总步数需求 ≈ Σ(每个模块的实现复杂度)
失败条件：总步数需求 > 步数预算
```

**四轮假设迭代，三个被推翻**（模块数、依赖链深度、静态可预测），
最终模型能解释全部 19 个任务。

**最强验证**：t8-001 在 30 步预算下 0/6，50 步预算下 4/5。

### 2. 边界任务可稳定复制

从 2 个成功案例归纳 5 条规则，按规则设计的 **8 个新任务全部命中 25–75% 边界区间**。

| 规则 | 说明 |
| --- | --- |
| 4–6 个待实现文件 | 太少秒过，太多超预算 |
| 每文件 15–30 行 | 同上 |
| 有依赖顺序 | 写错要返工 |
| 测试严格 | 边界条件 |
| 总实现量 90–130 行 | → 总需求 40–55 步 |

### 3. GRPO 的采样数决定训练是否有效

```
P(有梯度) = 1 - p^G - (1-p)^G
```

| G | 有效步率 | 可达环境 |
| --- | --- | --- |
| 1 | **0%** | 永远无梯度 |
| 2 | **60%** | 本地 8GB |
| 4 | 83% | 16GB |
| **8** | **93%** | **服务器 32GB** |

**这解释了为什么本地训练 failed——不是模型问题，是采样数的数学问题。**

## 四、十次自我修正

这个项目里 10 次用数据推翻了自己的结论：

| # | 错误结论 | 推翻方式 |
| --- | --- | --- |
| 1 | 循环率 87.4% | 修正指标定义（工具名 → 工具+参数） |
| 2 | 产出压力提升通过率 33%→100% | k=3 采样（两组都是 66.7%） |
| 3 | 长程失败是预算不足 | 19 步就能成功 |
| 4 | 长程失败是 write 不够 | 失败那次写了 8 次 |
| 5 | 模块数决定难度 | 6 任务 × 2 采样 |
| 6 | 依赖链深度决定难度 | 控制变量实验（10.5 vs 11.5） |
| 7 | 难度可静态预测 | 行数相关性弱，σ=0.53 |
| 8 | 稠密奖励是关键 | 本批稀疏奖励已有梯度 |
| 9 | 本地能训 GRPO | grad_norm 多次为 0 |
| 10 | 训练跑完 = 学到 | loss 低但 frac_zero_std=1.0 |

**这份记录比「一个漂亮的结论」更能说明工作方式。**
