# 信息可得性实验：agent 依赖验收标准而非独立理解

> 模型 `deepseek-v4.1-flash` · Docker 沙盒 · 纯代码判定（pytest 退出码）
> 任务：同一批任务在四种信息条件下重跑

## 一、实验设计

固定任务不变，只改变**模型能拿到的信息**：

| 条件 | 测试文件 | 题面 | 含义 |
| --- | --- | --- | --- |
| `full` | 可见（`test_*.py`） | 描述具体 bug | 完整信息（baseline） |
| `no_hint` | 可见 | 只说"让测试通过" | 少掉文字描述 |
| `hidden` | 在 `.hidden/` 子目录 | 不描述 bug | 需要主动探索才能找到测试 |
| `blind` | **完全不在 workspace** | 只说"有 bug" | 只能靠读代码推断 |

判定逻辑完全相同（同一份测试），只是测试文件对模型的可见性不同。

## 二、结果

| 条件 | t1_bugfix（20 题取样 10） | t2_feature（20 题取样 10） | 平均步数 |
| --- | --- | --- | --- |
| `full` | **10/10 (100%)** | **10/10 (100%)** | 6.3 |
| `no_hint` | **10/10 (100%)** | **10/10 (100%)** | 6.5 |
| `hidden` | **6/10 (60%)** | **6/10 (60%)** | 10.4 |
| `blind` | **0/10 (0%)** | **0/10 (0%)** | 11.2 |

**两个独立任务集的曲线完全一致**——不是噪声，是可复现的规律。

## 三、结论

### 1. 通过率单调依赖信息量，且两个模板精确重合

- 测试可见时：**100%**，无论题面是否描述 bug；
- 测试挪到子目录：掉到 **60%**（6/10，两个模板一致）；
- 测试不可见：**0%**（两个模板都是 0/10）。

### 2. 步数揭示了失败模式

| 条件 | 步数 | 解读 |
| --- | --- | --- |
| `full` / `no_hint` | 6.3 | 读测试 → 定位 → 修复，路径最短 |
| `hidden` | 10.4 | 需要先探索目录找到测试，多花 4 步 |
| `blind` | 11.2 | 无法读测试，只能反复试错，仍然失败 |

**盲改时模型并没有"放弃"**（步数反而最多），而是在**没有验收标准的情况下反复尝试**——这说明它的修复策略依赖测试反馈，而非对代码的静态理解。

### 3. 对 Agent RL 的直接意义

这是本项目里**唯一产生真实 gap 的维度**：

- `full` 条件下 100% 成功 → 可作 **chosen**
- `blind` 条件下 0% 成功 → 可作 **rejected**
- 两者任务相同、判定相同，**唯一的差别是信息输入**

因此可以构造**高质量的偏好对**：

```
prompt: 任务描述
chosen:  读测试 → 定位 → 修改 → 验证（6 步）
rejected: 反复试错 → 失败（11 步）
```

这正是训练所需的正负样本，且差异来源可解释（是否先获取验收标准）。

### 4. 训练启示

> 如果要用 RL 提升 agent 的编码能力，**收益最大的方向不是"更强地读代码"，而是"更主动地寻找验收标准"**。
> 一个能稳定做到"先找到测试再动手"的策略，就能把 0% 拉到 100%。

这与「先探索再行动」的 agent 训练目标一致，而不是「更强的单步推理」。

## 五、盲改下采样能否救回？（k=5 实验）

对 `blind` 条件（测试完全不可见）做 10 题 × 5 次采样：

| 指标 | 值 |
| --- | --- |
| 采样次数 | 50（实际完成 49） |
| 成功次数 | **0** |
| pass^5 | **0.000** |
| pass@5 | **0.000** |

**结论：采样不能补偿信息缺失。**

盲改不是「偶尔做对」，而是**结构性做不到**——模型 5 次独立采样、每次约 11 步探索，一次都没成功。
这与「任务太难导致偶发失败」有本质区别：

- 偶发失败 → pass@k 明显高于 pass^k → 有训练空间
- 结构性失败 → 两者都接近 0 → 需要改变**信息输入**，而不是增加采样

## 六、完整的实验图景

| 维度 | 结果 | 结论 |
| --- | --- | --- |
| 任务难度（加固 / 多缺陷 / 大型） | 100% 通过 | 难度不是瓶颈 |
| **信息可得性** | **100% → 60% → 0%** | **信息是瓶颈** |
| 策略复杂度 | 成本差 2.46 倍，成功率无差异 | 复杂策略无收益 |
| 采样次数（blind 条件） | 5 次仍 0% | 采样不能补偿 |
| 预算约束 | 阶跃（3–4 次调用） | 无中间态 |

**唯一有效的区分维度是「能否看到验收标准」。**

## 七、对 Agent RL 训练的具体建议

1. **任务设计**：要产生训练信号，必须让 agent 面对「验收标准不完整」的场景，
   而不是「代码更难」。前者产生 0%/60%/100% 的梯度，后者永远是 100%。
2. **偏好对构造**：`full` 轨迹（6 步、成功）vs `blind` 轨迹（11 步、失败），
   任务相同、判定相同，差异只来自「是否先找测试」——这是干净的偏好信号。
3. **训练目标**：不是提升单步推理，而是训练「先探索、再动手」的行为模式。
