# 运行时自愈 A/B 实验

## 这个实验回答什么

Agent 崩溃、被 Ctrl+C 打断、进程被杀之后，会话历史里会留下**不合法的转录本**（断头工具调用、孤儿结果、空 assistant 轮）。下一次请求时，主流 provider 会直接返回 400，用户看到的是「一句话都发不出去」。

这个实验量化：**运行时的转录本自愈到底值多少。**

## 方法

| 环节 | 做法 |
| --- | --- |
| 故障注入 | 直接向 Session 写入 32 例「崩溃后脏历史」+ 8 例干净对照（`scenarios.py`） |
| 严格 provider | 假 provider 按 OpenAI 的 tool-call 契约校验消息序列，不合法即抛 400（`strict_provider.py`） |
| 对照组 v0 | 把 `clean_provider_context` 在两处调用点（`agent.prompt_stream`、`loop._assistant_turn`）替换为直通 |
| 实验组 v1 | 完整运行时 |
| 指标 | **会话可继续率**：脏历史下再发一句话，能否被 provider 接受并正常 `end_turn` |
| 副指标 | 修复动作条数（+补齐 / -剥离），用于检查是否误伤干净历史 |

不调用真实模型、不产生费用，结果完全确定可复现。

## 运行

```bash
uv run python experiments/runtime_ab/run_ab.py
uv run python experiments/runtime_ab/run_ab.py --per-family 16 --json out.json
```

## 结果（per-family=8，共 40 例 / 80 次运行）

| 故障类型 | 样本 | v0 关闭自愈 | v1 完整运行时 | 平均修复动作 |
| --- | --- | --- | --- | --- |
| 断头调用 | 8 | 0/8 (0.0%) | 8/8 (100.0%) | +1.0 条 / 8 例触发 |
| 孤儿结果 | 8 | 0/8 (0.0%) | 8/8 (100.0%) | -1.0 条 / 8 例触发 |
| 空失败轮 | 8 | 0/8 (0.0%) | 8/8 (100.0%) | -1.0 条 / 8 例触发 |
| 混排 | 8 | 0/8 (0.0%) | 8/8 (100.0%) | -1.0 条 / 8 例触发 |
| 干净历史（对照） | 8 | 8/8 (100.0%) | 8/8 (100.0%) | +0.0 条 / **0 例触发** |
| **合计** | 40 | 8/40 (20.0%) | 40/40 (100.0%) | — |

**怎么读这张表**：

- 32 例故障历史在对照组**全部**被 provider 判 400（`stop_reason=error`），实验组全部恢复；
- 8 例干净历史两组都是 100%，且修复动作为 0 —— 说明自愈**不会误伤合法转录本**；
- 修复是「最小干预」：断头调用补 1 条合成结果，孤儿/空轮各剥离 1 条，不重写其余历史。

## 已知局限

1. 故障是**注入**的，不是真实崩溃现场录制的；形态参考了线上常见模式，但覆盖率有限。
2. 严格 provider 的校验规则是仿 OpenAI 契约写的，Anthropic 的约束更松，因此这里的数字是**下界之外的乐观情形**（真实 provider 可能更宽容）。
3. 只测「能否继续」，没测「继续之后回答质量是否下降」。

## 复现这条实验的最小改动

如果你 fork 了本项目：`scenarios.py` 里的四类故障是纯数据，可以直接加自己的案例；`strict_provider.py` 的校验规则也可以换成真实 provider 的报错回放。
