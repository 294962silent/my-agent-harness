## Mem0落后的已观察环节

词法答对、Mem0答错共8题，反向1题，对应完整29题净差-7。8题中3题Mem0标注会话覆盖不足，5题会话覆盖完整但仍答错。抽查后者中的10e09553、3e321797，词法均把具体答案chunk送入reader，Mem0均未送入。因此session Recall=1不等于答案片段进入上下文，不能将这些失败直接归因reader。

26道非弃答题：Mem0会话Recall>0为20题（11对9错），Recall=1为18题（11对7错）；词法对应23题（18对4错1不可用）和22题（18对3错1不可用）。4道弃答三臂均对，单列不混进召回分母。时间推理占词法单边正确的3题、知识更新占2题。

本批chunk上限800字符。用固定BGE tokenizer重建27517条索引文本，最长463tokens，超过512为0；Mem0选中的240个chunk也未超过512。**本次没有512-token截断证据**，不能把窗口长度当作已确认原因。CPU中文模型处理英文数据确有适配疑问，但语言、排序、阈值和无rerank的独立贡献仍需对照。

生产接法是Fact的key+value进入语义索引（memory.py:390），Mem0 infer=False（memory_mem0.py:95），search使用threshold0.1/top8/rerank=False（101–103），本地profile reranker=None（memory_local.py:269）。这轮评固定历史索引，不覆盖完整自动记忆抽取、更新或巩固效果。当前更具体的问题是语义排序/证据粒度失配；两例抽查不能推广为全部错误的唯一原因。

后续可分别验证：保持模型的词法/语义混合召回；保持检索流程更换多语embedding；固定候选集增加rerank与相邻chunk补全。每次只改变一个因素，另留未用于本次错误分析的测试题，不能只挑Mem0容易赢的例子。这里是建议，未实施或新增付费实验。

## RSI实际接到哪里

已接通的是“已评分train/holdout树→max_width/max_refine搜索→回放验证→registry晋升/回滚”。optimizer默认评估器为replay_trace（dream_rsi_optimizer.py:485–487）；active参数由replay读取（dream_rsi_replay.py:322–334）；worker运行TraceEnv.replay→ParallelRefineMethod.solve（_dream_rsi_worker.py:80–81）。

尚未接通生产Agent/CodingAgent自动导出独立评分的分支树，也未让Agent读取active控制真实下一动作/分支。开启入口不等于Agent已经在线优化。无数据调用返回needs_dataset；只读检查的本机默认registry为no_active_policy，未核任意自定义registry，不能推广成所有可能配置状态。

原设计按用户选择限定为受控策略参数优化；不是上游完整任意代码RSI或权重训练。当前缺口同时包含实际接线和真实效果证据，不能只说“接好了但还没跑分”。

## 如何形成长程能力证据

目前可以支持工程机制/停止保护的说法，不能支持长程任务质量优于基线或RSI带来提升。LongMemEval是记忆模块证据；本批Terminal科学配对无效；SWE-EVO仅评分环境及接口通过，尚无模型生成成绩。

建议优先补真实闭环：隔离分支执行、明确可用反馈、记录真实动作/成本/评分来源、训练集选策略、验证后发布、生产执行消费策略、独立未见任务验收。隐藏官方最终测试只在任务结束后评分，不把它作为在线选分支的反馈。离线已有评分树上的回放结果与真实在线评测分别报告。

证明时先保持同模型/工具/schema/总token或费用预算，比较固定策略、上下文/产物增强的固定策略、再加冻结RSI策略；预算保护与权限不关闭。RSI还应对照同预算的固定/随机探索，避免把增加分支计算量算作学习收益。训练/验证/最终测试按任务与仓库隔离，最终测试不参与反复选策略。

主任务采用SWE-EVO或明确里程碑的连续仓库开发，另设压缩后约束保持、取消与进程重启等故障注入专项；未实现的持久恢复先记缺口，不用Session文件存在证明恢复。主要指标为时限/预算内全部里程碑及最终回归通过率、约束遗忘/回归率、每成功任务总成本、故障后的工作损失。训练和评分调用也计费；有缺失用量不报完整费用。

先取得有效小样本配对再扩样，报告失效数量、同题配对差值与不确定性。真实RSI收益需在未见任务上、相同预算下复现，不能用合成树、SDK契约或CI测试数量替代。
