# 为什么本轮没有形成可归因的提升

2026-11-14。分析基于已封印的HumanEval校准数据和源码head `da63c824d7d2477ab3fa487f8cddc1c0cba7d7f7`；本次新增API调用0、重评分0，原始结果和策略均未修改。数值见[可重算诊断](no-gain-diagnostic.json)，原终态见[REPORT](REPORT.md)。

主要问题有三类：训练/测试的质量分数饱和；当前目标和搜索空间没有充分表达效率优化；任务没有给长程上下文增强施加足够的可观察压力。原权限失败与缺失schema是可靠性/证据问题，不能解释为RSI算法质量下降。

## 1. 基础组已经到达这批任务的质量天花板

- 3个train题、12个已记录节点的可见分数全部为1。
- 48个test槽首attempt均为`b0_a0`、visible=1；所有190个有可见分数记录的test attempt也都是1，另1个权限失败attempt无分数。
- 47个有效final所选候选全部为`b0_a0`，这些被选中的首分支全部通过独立final。A组12/12已经通过，B组同为12/12。

因此，在已评分的47个槽上，后续探索没有换出更高评分的最终产物。这支持“这批题无法显示额外探索的质量收益”，不能推广为所有任务都不需要探索；未选中候选和未评分槽的隐藏质量也仍然不可得。

这轮的工程校准目标已完成；要检验收益，应先在独立train先导中确认存在“初解失败、后续分支改善”的样本。仅继续重复同类满分题，无法创造新的学习信号。

## 2. 当前选参目标丢弃了效率差异

[选参目标与排序](../../../../src/my_coding_agent/dream_rsi_optimizer.py#L256)以train题×动作预算下的recorded-best-ratio均值排名。它没有把真实请求数、tokens、耗时或金额纳入目标；平分先选fixed reference，再比较宽度/深度。

实际5种策略的train分数全为1。在预算4的离线回放中，c00只用1个tree action就拿1分，reference用4个动作也拿1分；当前规则仍因质量平分选择reference。这里不能说“候选更贵，所以没选中”，而应说目标没有奖励较少探索。

tree action是回放中访问记录节点的动作，不等于真实API请求或tokens。实际SDK合计48个评估叶、82次离线action，不能据此直接计算线上节省。

## 3. 四个候选没有覆盖四种有效行为

[候选生成](../../../../src/my_coding_agent/dream_rsi_optimizer.py#L149)截取网格前缀。本次`max_candidates=4`取得的组合全为width=1，refine分别为0/1/4/64，没有覆盖width=2的候选。

已有树只有两条分支、最大refine深度1。[回放器](../../../../src/my_coding_agent/dream_rsi_replay.py#L300)只能使用已记录树，因此后两个更深候选被裁为当前树上的refine=1：四个名义候选主要只有`(1,0)`与`(1,1)`两种有效覆盖行为。这个诊断来自候选与树的实际范围，不是效果提升的推测。

修正应先在合法树边界内覆盖宽/深组合并按有效行为去重，再受候选预算限制。扩大一个已饱和浅树上的重复回放不会自动生成新分支。本轮源码尚未做此修改，当前test也不用于重选候选。

## 4. C没有新的学习干预，random也主要是顺序对照

SDK选中baseline/null；C在线使用预先登记的reference2/1，与B同参数。因此C−B不能估计新学习策略的贡献，也不能把“无可识别效应”写成“学习提升0%”。

[线上调度](../../../../src/my_coding_agent/rsi_runtime.py#L354)的fixed/rsi走同一节点规划分支；random主要改变细化与开新分支的次序。在本次2×2节点与充分额度下，正常完成会遍历同样四个节点。test没有父预算/子轮额耗尽，唯一未交付来自权限异常。

[候选更新](../../../../src/my_coding_agent/rsi_runtime.py#L439)只在分数严格变高时替换selected；score=1后也没有质量早停。因此所有后续分数同为1时，首个胜出者一直保留。

当前是受控width/refine参数优化首版，线上计划的适应性有限。优化器未生成新的策略程序或更新模型权重；执行Agent仍照常生成候选代码。真实执行/优化/消费链路接通和学出更优策略是两个验收条件。

## 5. 后续探索有成本，早停收益仍需独立验证

仅test48的已发生成本：

- 首attempt：259请求、649834tokens。
- 后续attempt：626请求、1979399tokens，约占test tokens的75.3%。
- 合计885请求、2629233tokens，request scope全部可归属。

这些是观察到的成本分账，不是“早停一定省75.3%”的反事实实验。新的停止规则可能改变轨迹、检查开销与失败率；可见例满分也不保证隐藏测试通过。

下一批应把早停作为固定/随机/学习策略都可使用的同一动作，在独立任务上检验何时停止。固定对照还应包含首解即停的贪心策略，防止只拿始终做四次尝试的方案作为效率基线。

## 6. 当前输入远小于配置窗口，没有检验越窗收益

test实际provider输入峰值为A7627、B5090、C5897、random4598tokens；客户端配置窗口32000。layered的已记录估计视图峰值为B5254/C6019/random4951，均低于记录的25600触发阈值。

完整canonical历史峰值与服务端有效窗口未记录，不能用发送视图倒推出全部原始历史；summary请求0也不能单独证明从未近窗。但结合基础组输入峰值与增强组视图观测，本批没有展示出需要持续越窗压缩的任务负载。

实际机制并非全未触发：test phase-fold为70个snapshot-derived views，collection另8个，v2共78；micro为3个test snapshot groups，collection为0。它们不是执行次数。summary purpose请求0，显式artifact_read/search recorded starts0；不能把这些计数写成成功回读次数。

v2约286.6万tokens分散在53个episode和多个分支上；另有v1及连通的8551tokens，本批总量约287.5万。累计消费大，不代表某一条任务历史长。单函数、多次短尝试无法替代多文件修改、长期约束、反复验证、大日志回读、中断恢复等长程压力。

## 7. B有描述性成本差异，但没有稳定降本结论

A为221请求701172tokens；B为231请求670237tokens。B总tokens少30935（约4.41%），请求多10（约4.52%），单请求tokens少约8.55%。

按12个task/seed组做事后描述性拆解：B−A token差值7负5正，中位−1390，范围−35670到+21135。HumanEval/20两次重复合计−56233；其余五题合计反而+25298。不能把总量差异解释成每题都变省。

输入减少25119、输出减少5816，但各臂生成轨迹和输出内容不同。现有数据不能把投影机制、调用次数、模型随机性各自贡献拆开；temperature=0.7，调度seed也不是服务端确定性seed。独立问题只有6个，不是48个，更不是974个。

该分解仅解释已有数值，未放宽原主分析器同schema门禁，不作排名、p值或稳定提升结论。C的10请求22670tokens权限失败仍保留，不能拿其提前终止的低成本作为效率成绩。

## 8. 证据缺口与集成范围需要分开解释

val32轮额耗尽导致完整验证覆盖不足；test原权限失败没有final，第三attempt没有schema指纹。190个已记录指纹一致，null是证据缺失，不能当作实际工具漂移，也不是模型没解出来的证据。

这轮没有评估Mem0召回质量；Langfuse是观测层，是否上传可靠、带来多少开销也未在这轮做消融。不能用本轮RSI/上下文结果判断整个三项集成无效。缓存字段仍只覆盖v2的964/969请求，完整总体命中率不可得。

## 下一批应先满足的条件

1. 在独立train先导中检查题目区分度和候选改善，不用当前test筛题、调目标或重报泛化。
2. 修正有效候选覆盖/去重；完整holdout可交付后才验收候选，失败与成本继续保留。
3. 预注册“质量达标后最小化真实tokens/请求”等质量与效率目标；回放action只作代理量，独立验证实际调用成本。
4. 为所有对照提供相同合法动作与预算，加入强贪心对照，检验探索/细化/停止，而非只比较穷举顺序。
5. 用真正多轮、多文件、大输出、旧约束和恢复任务测试Context/Artifact；机制层同轨迹投影与真实模型端到端实验分别报告。
6. 分开记录configured schema与实际发送hash，补充安全错误诊断，按预注册规则处理未发送/缺失，当前原null不回填。

以上是分析后的建议方案，尚未修改生产策略或启动新模型实验。下一阶段目标应是获得可区分、可验证的学习信号，而不是让当前满分校准继续累积调用量。
