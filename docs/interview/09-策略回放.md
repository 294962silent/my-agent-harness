# 受控策略自优化：Dream-RSI 参数闭环

这是原八模块之外新增的受控策略入口，不计入原12场景/100观测。本轮已接显式在线分支执行，还没有真实模型效果消融成绩。

## 面试要解释的问题

为什么普通Session不能直接充当搜索树？已评分树的离线回放能验证什么？固定参考策略、学习得到的策略和在线自改有什么区别？

## 实现与取舍

`my-agent-dream`读取有baseline、父子关系、branch/attempt与评分的v1输入。新增optimize会冻结白名单参数网格，用train选择唯一候选、holdout验收，与baseline及冻结active比较；可信动作/成本重算，严格改善且实绩数据完整才可晋升。合成只dry-run，无数据needs_dataset。本轮没有真实数据，生产active保持baseline。

源码：`dream_rsi_contract.py`、`dream_rsi_optimizer.py`、`dream_rsi_registry.py`及既有replay/worker；入口和SDK Git来源由pyproject/uv.lock绑定。参数实际传入固定可信官方策略类，正常replay默认消费合法active。不可变版本、原子active/previous和锁内CAS防训练期间被其他晋升/rollback覆盖，也防ABA；失败保持旧active，损坏明确回退。

## 开发问题

固定上游SHA的OptimalPolicy模板实际为空。只根据类名接入会制造“策略已运行”的假象；进一步读取入口后改用真实可执行的ParallelRefineMethod，并去掉实际不会生效的beta参数。

进一步核查上游自动代码优化会信任候选自报SimResult。首版按用户选择只允许max_width/max_refine纯参数，执行器/评分器不让候选改写；用固定前置候选集合和独立验证，避免把伪造reward或验证集选参当提升。指标是归一化回放best均值，不冒称论文AUC或任务成功率。

现有 SWE 单链和 Session 缺少评分分支结构，不能给消息编分数来兼容。本轮新增 `rsi_runtime.py` / `rsi_branch.py`：现有 CodingAgent loop 执行分支，host 可见测试评分；合法完成前缀导出 trace，train/holdout/test 校验任务隔离。冻结策略实际控制宽度/继续尝试次数，可读取 registry active。独立 final 后置，反馈不进 trace；分支目录非 OS 沙箱。

## 已验证与尚未验证

真实 SDK 契约验证回放决策、合成不晋升、合法 active 消费与损坏回退；注入评估器验证晋升门槛/CAS，不是真实收益。本轮 CLI 已执行 CodingAgent → 文件工具 → 本地测试 → trace → SDK dry-run → 冻结策略 → A/B/C/random，主代理独立复跑一致。模型仍 scripted，C 少调用为夹具行为。RSI 44项专项与最终整库回归通过；首版不支持 TUI 流式 RSI。

详见[执行接口](../rsi-runtime.md)、[证据](../experiments/results/context-rsi-20261113/rsi-contract/REPORT.md)与[工程深挖](11-RSI闭环与本地推理工程深挖.md)。真实实验须先处置既有未知费用，再冻结新协议；不自动恢复旧 benchmark。
