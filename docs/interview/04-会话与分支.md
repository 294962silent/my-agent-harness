# 会话与分支：恢复路径和摘要身份

## 面试要解释的问题

为什么会话树和代码工作区快照不是一回事？resume 能否保证工具 exactly-once？摘要覆盖 count 如何避开 system 偏移？

## 实现与取舍

保留 JSONL 与 Entry Tree，按当前分支重建历史，摘要绑定 canonical 覆盖身份。已有可靠性增强来自前一批；本批新增统一对照与可复算证据，没有把它重新包装成新写的存储引擎。

线性读取全部 Entry 简单，但会混入兄弟分支。当前路径恢复保留分支语义；分支恢复本身不能解决工作区文件或外部数据库状态回滚。

源码：`src/my_agent_core/session/、context.py`。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `branch_restore` / `off` / `comparison`：观测 `{"branch_leaks": 1, "messages": 3}`；5/5 次满足各自预注册的夹具断言。

- `branch_restore` / `on` / `comparison`：观测 `{"branch_leaks": 0, "messages": 2}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

早期摘要按全树深度选择会误用其他分支；前一批已修覆盖身份，本批又验证相同尾部、改写前缀时旧摘要失效。

## 优势、代价与不能据此宣称的结论

branch_restore 的 off 是明确标注的线性投影对照实现，不是生产环境可关闭的分支开关。重复五次仍只有一个分支结构场景。

## 复现

`python -m experiments.harness_eval --suite session --repeats 5 --output <新目录> --seed 23`。需要从仓库工作目录加载 `src`；结果目录不可同名覆盖。使用脚本provider / 临时文件，模型tokens、cache、质量字段为null。
