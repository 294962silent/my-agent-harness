# 模型门面：流生命周期和供应商边界

## 面试要解释的问题

生成器创建和首次迭代为什么不同？外部取消如何穿过两层 async generator？usage 缺失为何不能记零？

## 实现与取舍

保留 Provider 消息转换，统一 chat / achat / stream / achat_stream / astream_events 的观测包装。流首次迭代才开始记录，耗尽、异常、取消和显式关闭各有恰一终态，底层流也须关闭。

直接在每个 provider 重复埋点容易漏掉新入口；只监听 Agent 又会漏摘要和记忆抽取。选择门面封装，但直接调用 Provider 或自定义假 LLM 不自动在覆盖范围内。

源码：`src/my_agent_llm/client.py、observation.py、providers/`。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `stream_cancel` / `contract` / `contract`：观测 `{"cancellation_propagated": 1, "provider_finalized": 1}`；5/5 次满足各自预注册的夹具断言。

- `stream_close` / `contract` / `contract`：观测 `{"provider_finalized": 1, "terminal_records": 1}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

流暂停后若 ContextVar 跨 yield 挂在调用方，后续独立调用会误继承 parent。实现把作用域限定在每次迭代内部；并发 r1/r2 和 sibling parent 最小探针确认隔离。

## 优势、代价与不能据此宣称的结论

usage 是 provider 已归一化的用量快照，不是完整原始账单；流累计块不能相加。两个脚本流契约不代表真实网络取消延迟。

## 复现

`python -m experiments.harness_eval --suite model --repeats 5 --output <新目录> --seed 23`。需要从仓库工作目录加载 `src`；结果目录不可同名覆盖。使用脚本provider / 临时文件，模型tokens、cache、质量字段为null。
