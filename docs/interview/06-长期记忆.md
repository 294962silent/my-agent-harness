# 长期记忆：来源、失效和受控回读

## 面试要解释的问题

显式删除与 supersede 有何差异？如何保证删后重载不复活？为何不同时让本地和Mem0各抽一次？

## 实现与取舍

保留 Markdown 为事实来源、FTS/BM25 为可重建索引；精确 subject/key、supersede 历史、NOOP、delete、脱敏与全文回读已在前一批交付。自动抽取默认关闭，启用时只接受带来源标记的用户原文 evidence。

Mem0可提供语义召回，当前已作为可选候选索引接入；本地facts/tombstone继续为权威。纯文本infer=False，候选按scope/identity/revision及active/删除状态重验，正文只从本地取；索引失败回退原词法。没有引入双抽取或远端事实回灌。

源码：`src/my_agent_core/memory.py、memory_index.py、memory_distillation.py、memory_safety.py`。

新适配源码：`memory_semantic.py、memory_mem0.py`，配置/生命周期接线位于CodingAgent、Settings和RPC。只允许全局settings启用外发集成，项目配置不能覆盖；显式Python注入默认caller-owned。

本机后续选择本地CPU中文后端：`memory_local.py`使用固定BGE-small-zh-v1.5、512维、显式CPU和NeverLLM，不需embedding API/key。模型缓存逐文件验hash，多个adapter共享只读权重但独占可写候选库；事实主存储位置保持。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `labeled_retrieval` / `off` / `ablation`：观测 `{"hits": 0, "labeled_queries": 2, "recall": 0.0, "stale_hits": 0}`；5/5 次满足各自预注册的夹具断言。

- `labeled_retrieval` / `on` / `ablation`：观测 `{"hits": 2, "labeled_queries": 2, "recall": 1.0, "stale_hits": 0}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

脱敏正则曾误伤 max_tokens/token_budget，已收紧；无有效 evidence 的非空响应曾推进成功游标，已补负例修复。本批通过门面观测记录辅助抽取，用量不遗漏于主循环之外。

## 优势、代价与不能据此宣称的结论

当前检索实验仅两条标注查询，是 smoke，不足以证明长期记忆质量；无跨进程写锁。目录决定作用域，旧备份未安全擦除，有界抽取可能漏掉中段事实。

## 复现

`python -m experiments.harness_eval --suite memory --repeats 5 --output <新目录> --seed 23`。需要从仓库工作目录加载 `src`；结果目录不可同名覆盖。使用脚本provider / 临时文件，模型tokens、cache、质量字段为null。

## 后续Mem0适配证据与边界

真实固定2.2.1 SDK经生产adapter→MemoryStore→本地Qdrant，使用确定性假embedding并禁止LLM和网络，验证metadata/search/delete及关闭后同路径重建。发现SDK的Memory.close只关SQLite，适配器补关自有向量/HTTP客户端；超时单worker熔断，close在途返回False。此证据支持调用和生命周期，不支持语义召回收益。参见[三项集成说明](../integrations/README.md)；效果benchmark已按用户要求延期。

最新增加真实CPU模型功能检查：网络连接被拒绝、词法fallback临时被禁止，仍从生产Mem0Index取回本地事实，实际ORT provider只有CPU；关闭后模型强引用与独占缓存释放。功能smoke不等于标注集召回消融，尚不宣传recall提升。本机配置已启用，进程重启读取。
