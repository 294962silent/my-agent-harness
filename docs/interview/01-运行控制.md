# 运行控制：唯一归属、取消与预算

## 面试要解释的问题

为什么对消费者暂停期间不直接取消消费者？begin_turn 为什么放在重试外？第二次 prompt 是排队还是拒绝？

## 实现与取舍

原来直接运行可以覆盖同一 Agent 的共享取消令牌，循环缺少执行上限。本批把一次调用的 run_id、signal、预算和清理责任集中进 RunState；第二个直接调用明确拒绝。max_turns 在主模型轮开始前计数，重试不增加轮次，max_seconds 使用单调时钟限制异步等待。

排队协调器能接受更多请求，但还需要投递与会话切换协议；本批选择小接口拒绝并发，先保证归属正确。默认预算无限以兼容旧调用，产品入口可以明确传 RunLimits。

源码：`src/my_agent_core/agent.py、loop.py、run_lifecycle.py`。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `single_owner` / `contract` / `contract`：观测 `{"concurrent_prompt_rejected": 1, "owner_released": 1}`；5/5 次满足各自预注册的夹具断言。

- `turn_budget` / `off` / `ablation`：观测 `{"budget_exhausted": 0, "model_calls": 5}`；5/5 次满足各自预注册的夹具断言。

- `turn_budget` / `on` / `ablation`：观测 `{"budget_exhausted": 1, "model_calls": 2}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

第一次按 deadline 立即取消时，provider 已交付 tool_calls 的会话留下未配对调用。集中终止收尾只保存已经观察到的工具意图并补恰一条中断结果；新增 abort、deadline、消费者关闭后的 Session.load 回归。

## 优势、代价与不能据此宣称的结论

同步 Python / 同步 SDK 不协作时无法强制抢占；外部副作用不能回滚。调用方 CancelledError 必须传播，不能假装任务正常完成。

## 复现

`python -m experiments.harness_eval --suite runtime --repeats 5 --output <新目录> --seed 23`。需要从仓库工作目录加载 `src`；结果目录不可同名覆盖。使用脚本provider / 临时文件，模型tokens、cache、质量字段为null。
