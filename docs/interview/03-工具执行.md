# 工具执行：独立并发与依赖顺序

## 面试要解释的问题

为什么一个工具不安全时整个批次串行？线程工具超时后还能继续写吗？何时应该建立显式依赖图？

## 实现与取舍

保留真实注册表与工具元数据；安全独立批次可并发，有副作用或依赖的批次按现有策略串行。本批把工具等待纳入运行预算，并增加统一原始观测。

全串行容易推理但独立I/O等待无法重叠；全并行可能读到写入前状态。声明式并发安全与批次门控使执行规则可审查，不能自动推断任意工具之间的数据依赖。

源码：`src/my_agent_core/registry.py、tools.py、loop.py`。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `safe_parallel` / `off` / `ablation`：观测 `{"completed": 3, "peak_concurrency": 1}`；5/5 次满足各自预注册的夹具断言。

- `safe_parallel` / `on` / `ablation`：观测 `{"completed": 3, "peak_concurrency": 3}`；5/5 次满足各自预注册的夹具断言。

- `write_read_dependency` / `off` / `comparison`：观测 `{"dependency_violations": 1}`；5/5 次满足各自预注册的夹具断言。

- `write_read_dependency` / `on` / `comparison`：观测 `{"dependency_violations": 0}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

旧实验曾只看并发更快，却遗漏读写依赖违例。本次同时测peak_concurrency、completed和dependency_violations，区分生产开关消融与故意全并行的对照wrapper。

## 优势、代价与不能据此宣称的结论

三个受控异步读工具的局部耗时不代表整个Agent任务加速；同步工具无法被Python协作取消强停，外部副作用无法回滚。
