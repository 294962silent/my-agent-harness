# 工具权限：副作用前的授权

## 面试要解释的问题

工具名未知时为何默认拒绝？只读命令是否一定没有副作用？权限和路径归属校验各承担什么？

## 实现与取舍

沿用默认 fail-closed 的权限门禁，明确只读 memory_read / artifact 回读与写工具的区别。本批通过真实权限调用、临时文件和单变量对照测副作用，而非只检查提示文案。

只依赖模型遵守提示没有执行层约束；统一授权 hook能在工具副作用前阻止操作。它仍只看单次调用，不等同完整信息流安全系统。

源码：`src/my_coding_agent/permissions.py、src/my_agent_core/hooks.py`。

## 本轮实际离线证据

运行：[`20261112T095857-2381042b458f`](../experiments/results/redesign/20261112T095857-2381042b458f/report.md)，seed=23，每个 arm 五次；完整运行共 12 个独立场景、100 条记录。

- `unauthorized_write` / `off` / `ablation`：观测 `{"unauthorized_side_effects": 1}`；5/5 次满足各自预注册的夹具断言。

- `unauthorized_write` / `on` / `ablation`：观测 `{"unauthorized_side_effects": 0}`；5/5 次满足各自预注册的夹具断言。

off组满足断言可能意味着它如预期暴露缺陷，不代表off更安全。contract没有开关；comparison的对照是有限wrapper，不能称生产模块可关闭消融。

## 遇到的问题与解决

历史 read(.env)+write(public) 可以分别符合单次权限而组合泄漏，尚未实现组合风险识别。面试材料保留这个缺口，不把一个拒写用例当作全面安全证明。

## 优势、代价与不能据此宣称的结论

夹具只覆盖一条未授权写入，不能给通用攻击防御率；授权策略必须随工具扩展维护。

## 复现

`python -m experiments.harness_eval --suite permission --repeats 5 --output <新目录> --seed 23`。需要从仓库工作目录加载 `src`；结果目录不可同名覆盖。使用脚本provider / 临时文件，模型tokens、cache、质量字段为null。
