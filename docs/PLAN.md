### 阶段 1：pi-agent 逆向与量化对比（核心任务）
**目标**：精确回答「我们借鉴了 pi 多少、改了多少」。

| 动作 | 方式 |
| --- | --- |
| 下载 pi 官方包 | `npm pack @earendil-works/pi-coding-agent`（允许下载） |
| 解包并统计源码规模 | 文件数、行数、模块划分 |
| 逐模块建立对照表 | pi 的函数签名 ↔ 我们的实现 |
| 计算相似度 | 借用结构 / 重写 / 原创 三分类，给出比例 |

**产出**：`docs/01_PI_DIFF.md`
- pi 的架构全景（模块图）
- 逐模块对照矩阵（借了什么、改了什么、为什么改）
- **量化结论**：结构借鉴 X%，代码重写 Y%，原创 Z%

**子代理分工**：派一个子代理专做 pi 包逆向（下载 + 解包 + 统计），
主线程同时推进其他阶段。

### 阶段 2：横向方法对比（工业软件 7 家）
**目标**：每个核心设计点，说明「别人怎么做、我为什么不同」。

对比对象（用户指定）：
1. **Codex**（OpenAI）
2. **Claude Code**（Anthropic）
3. **DeepSeek Harness**（本仓库所在环境）
4. **Kimi Work**（月之暗面）
5. **Trae**（字节）
6. **WorkBuddy**
7. **pi-agent**（Earendil Works）

对比维度（每个模块都过一遍）：

| 维度 | 说明 |
| --- | --- |
| 调度模型 | 单层 ReAct / 两层 Loop / 事件驱动 |
| 上下文管理 | 压缩策略、KV cache 保护 |
| 工具系统 | 并发模型、权限门禁、截断策略 |
| 会话存储 | 树状 / 线性 / 分片 |
| 扩展机制 | Plugin / Extension / MCP |
| 记忆系统 | 抽取-巩固-检索的实现差异 |
| 子代理 | 同步 / 异步 / 隔离级别 |

**方法**：
- 有公开资料的（Codex/Claude Code 有文档和开源部分）→ `web_search` + `web_fetch`
- 闭源的需要逆向或看文档 → 子代理负责搜集
- 能下载的就下载（npm/pip 包）分析结构

**产出**：`docs/02_LANDSCAPE.md`（对比矩阵 + 每家的设计取向总结）

| 多智能体 | subagent delegation, hierarchical agent |
| 评测 | agent benchmark, terminal-bench, SWE-bench |

重点会议/期刊：NeurIPS 2025、ICLR 2026、ACL 2025/2026、OSDI/SOSP 2025、
MLSys 2025/2026、arXiv 最新。

## 三、执行策略

### 并行安排

```
主线程                          子代理 A                子代理 B
──────────────────────────────────────────────────────────────
阶段 0 事实基线                  pi 包逆向               工业软件资料搜集
    ↓                              ↓                        ↓

    ↓
阶段 5 验证闭环
    ↓

```

### 关于 opencode go

涉及 API 调用、KV cache 实测的任务（阶段 5 的实验复现），
用 opencode go 执行，避免消耗太多本地资源。

### 证据要求（硬性）

**所有数字必须有出处**。文档里每个实测值后面标注：
- 命令（可复现）
- 或文件路径 + 行号
- 或日志文件

不允许出现"大约""估计""应该"这类表述。
