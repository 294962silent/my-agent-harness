### A4「KV cache 命中率」——具体多少？

## B 组：设计决策（考察是否真懂）

### B1 为什么工具并发用「批级门控」而不是 DAG？

**可以放心讲**：

1. DAG 要静态分析工具的读写集
2. 但 `bash` 无法静态分析（`echo hi > a.txt` 写了什么？）
3. `edit` 的写入位置依赖文件内容（oldText 匹配到哪）
4. **结论**：正确性成本远高于收益

**追问：那你知道谁用了 DAG 吗？**
知道。LLMCompiler（ICML 2024）用 Planner + Task Fetching Unit + Executor 三段做 DAG 化。
但它面向的是**可静态分析的工具**。

**追问：Codex 怎么做？**
Codex 用 Rust 的 `RwLock`：工具声明 `supports_parallel_tool_calls()`，
拿读锁可并发，拿写锁排他。**也是无参数声明，和我的选择一致**。
唯一看参数的是 dsh（`isConcurrencySafe(args)`）。

### B2 为什么循环用「纯函数生成器」而不是类？

**可以放心讲**：

| 维度 | 类方法 | 纯函数生成器 |
| --- | --- | --- |
| 状态 | 类实例持有 | 参数传入 |
| 副作用 | 类内部直接 IO | 只 yield 事件 |
| 可测试 | 需 mock 整个类 | 直接消费事件流 |
| 复用 | 绑定一种界面 | CLI/TUI/RPC 共用 |

**追问：这是你原创的吗？**
不是。代码里明确写了「对标 Tau 的极简纯函数异步微内核」。
但我做了工程化——加了 `agent.py`（559 行）做装配。

### B3 上下文压缩为什么是 3 层？

**可以放心讲**：

| 层 | 触发 | 手段 | LLM 调用 |
| --- | --- | --- | --- |
| 0 | <80% 阈值 | 什么都不做 | 0 |
| 1 | 超阈值 + 有超大输出 | 工具输出落盘 | **0** |
| 2 | 还超 | 离散块摘要 | 1 |

**核心论点**：压缩是为了省 token，但如果破坏 prefix cache，反而更贵。
所以「能不压就不压」。

**追问：Claude Code 有几层？**
**4 级**：工具结果落盘（≤50k 字符）→ 无模型裁剪 → 微压缩 → 全量摘要，
外加 413 反应式压缩。我们缺后三层。

**追问：dsh 呢？**
可插拔 seam，公式 `floor(min(W×0.8, W−O−64K))` + 保留最近 16% 逐字，
**压缩前先剪工具输出（不调模型）**——这一层和我们一样。

### B4 为什么会话用树状而不是线性？

**可以放心讲**：fork 成本 O(1)（新分支只是新 parentId），不用复制历史。

**追问：为什么不学 dsh 存事件、消息靠投影？**
⚠️ **其实我们接近 dsh 的方案**。Entry 本质是事件，
活跃分支通过 `path_to_entry` 投影出来。差别是 dsh 把压缩也做成一条事件。
**dsh 有个我们没做的**：压缩锁最后释放，崩溃留「孤儿锁」而不是假的「已完成」。

### B5 权限门禁为什么是 fail-closed？

**这是最好的案例，可以放心讲**：

原实现是 fail-open（没有回调时默认放行），结果是
**用户在 TUI 点「拒绝」，文件还是被写了**。

这是典型的**静默失效**——不是崩溃，是系统"正常工作"但结果是错的。

修复：非 autonomous 模式没有 `confirm_callback` 一律 block。

**追问：怎么验证的？**
端到端，不是单测：批准→验证文件存在；拒绝→验证 `Tool 'write' blocked` **且文件不存在**。
关键是验证"文件真的没写"，只验证报错信息不够。

# 第二部分：创新点提炼（可加入简历）

## 亮点 1：跨产品横向调研的量化结论 ⭐⭐⭐

**这是本次工程最有价值的产出**，因为它展示了**判断力**而非执行力。

**可写进简历的表述**：

> ● 系统调研 10 个主流 Agent Harness（Codex / Claude Code / Kimi CLI / Trae / dsh /
>   WorkBuddy / OpenHands / SWE-agent / Aider / pi），归纳出**工具并发的四种正交范式**
>   （读并写斥 / 全串行 / 自声明+上限 / 子代理爬坡）与**三种会话存储哲学**
>   （存消息 / 存事件靠投影 / 存 git）；
>   发现 **prefix cache 保护是拉开工程水平的分水岭**——仅 2/10 产品将其作为显式设计目标。

**为什么这是亮点**：大多数候选人只会说"我做了个 agent"，
说不出业界有几种做法、各自代价是什么。

## 亮点 2：与 pi 的量化差异化 ⭐⭐⭐

> ● 反编译统计 pi 官方 6 个 npm 包（108,459 行 TS），对标重写为 18,170 行 Python（16.8%）；
>   **结构借鉴 32% / 重写 37% / 原创 32%**。三处本质改动：
>   ① 循环从 `AgentSession` 类改为纯函数异步生成器（可单测、三界面复用）；
>   ② 工具并发从文件级队列锁改为**批级门控**（零静态分析依赖，因 bash 副作用不可静态分析）；
>   ③ 上下文压缩从单层摘要改为**三层惰性管线**（新增「工具输出落盘」零 LLM 调用层以保 prefix cache）。

**为什么这是亮点**：能精确说出"我借鉴了什么、改了什么、为什么改"，
这是工程成熟度的体现。

## 亮点 3：Token/成本效率（新的强指标）⭐⭐⭐

> ● Terminal-Bench 2.1 实测 71/89（79.8%），对齐官方 pi 的 72/89；
>   但 **token 消耗 41.7M vs 122.3M（省 66%）、费用 $4.62 vs $18.84（省 75%）**；
>   逐任务呈 6 胜 7 负交叉分布，证明为独立实现而非数据复制。

**为什么这是亮点**：**同样效果少花 75% 的钱**，这是工程优化的直接体现，
比"我也做到了"更有说服力。

## 亮点 4：缺陷驱动的工程闭环 ⭐⭐

> ● 通过外部评审发现并修复 3 个 P0 + 7 个 P1 缺陷，其中两个典型：
>   ① **权限门禁静默失效**——单测通过但未接入主链路，用户点「拒绝」文件仍被写入；
>      改为 **fail-closed**（无回调一律 block），端到端验证「拒绝后文件不存在」；
>   ② **API Key 泄漏到子进程**——`/login` 写入 `os.environ` 被子进程继承，
>      改为子进程 env 白名单。测试基线 828 → 956。

**为什么这是亮点**：能讲出"最危险的 bug 不是崩溃而是静默失效"这个洞察。

## 亮点 5：学术空白识别 ⭐⭐

> ● 调研 2025-2026 年 52 篇 agent harness 相关论文，识别 4 个明确学术空白：
>   工具并发副作用语义理论、**子代理委派定量收益归因（至今无受控实验）**、
>   harness 级 scaling law、树状会话作为规划原语。

**为什么这是亮点**：显示有做研究的能力，适合投后训练/研究岗。
